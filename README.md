# 전국 공공도서관 데이터 정제·검색 자동화 도구

## 1. 프로젝트 소개

공공데이터 CSV를 안전하게 읽고 도서관명·지역 조건으로 도서관을 찾는 Python 도구입니다.

현재는 **CSV 로더와 도서관명·지역 검색 CLI, 도서관별 세로 출력**을 구현하고 전체 pytest **49개 통과**를 확인했습니다. 검색은 [GitHub Issue #1](https://github.com/kchvbcd-wq/public-library-data-tool/issues/1)의 Acceptance Criteria를 기준으로 개발했습니다. 검색과 출력 개선 코드는 `feat/library-search-cli` 브랜치에서 `71bd4dc`로 커밋하고 GitHub에 Push했습니다. 데이터 값 검증, 정제, 지도 기능은 아직 구현하지 않았습니다.

## 2. 프로젝트를 개발하는 목적

공공데이터를 활용해 **문제 정의 → 기능 설계 → 구현 → 테스트 → 실제 실행 → 오류 발견 → 개선 → GitHub 기록**의 개발 과정을 직접 경험합니다.

ChatGPT와 Codex로 코드 초안을 작성하되, 개발자가 원리를 이해하고 실제 파일과 자동 테스트로 동작을 확인하는 것을 목표로 합니다. 작은 기능부터 완성하고 실패 상황을 검증하면서 유지보수 가능한 코드를 쌓아갑니다.

## 3. 해결하려는 실제 문제

공공데이터 CSV를 분석에 사용하려면 먼저 파일을 정확하게 읽어야 합니다. 인코딩이 맞지 않으면 한글을 읽을 수 없고, 실행 위치에 의존하는 경로는 파일 탐색 실패를 일으킬 수 있습니다. 빈 파일이나 필수 컬럼이 빠진 파일을 정상 데이터로 취급하면 이후 작업에서 원인을 찾기 어려워집니다.

또한 숫자처럼 보이는 기관 코드와 전화번호를 자동 변환하면 원래 표현이 달라질 수 있습니다. 이러한 로딩 문제를 명확한 오류 메시지와 테스트로 확인하고 원본의 구조와 값을 보존합니다. 전체 표를 직접 살펴봐야 했던 불편은 도서관명·지역 검색으로 줄이고, 후속 데이터 검증 작업의 기반을 마련합니다.

## 4. 활용한 공공데이터와 출처

- 데이터명: **전국도서관표준데이터**
- 제공 플랫폼: 공공데이터포털
- 출처 및 다운로드: [전국도서관표준데이터](https://www.data.go.kr/data/15013109/standard.do)
- 프로젝트 원본 경로: `data/raw/전국도서관표준데이터.csv`

현재 보관한 원본 파일을 직접 확인한 결과입니다.

| 항목 | 확인 결과 |
| --- | --- |
| 인코딩 | CP949로 엄격한 해독 성공, UTF-8 해독 실패 |
| 데이터 행 수 | 3,597행, 헤더 제외 |
| 컬럼 수 | 28개 |
| 주요 컬럼 | 도서관명, 시도명, 시군구명, 도서관유형, 휴관일, 소재지도로명주소, 데이터기준일자 |

행 수와 컬럼 수는 현재 로컬 파일의 확인값이며 코드에 고정하지 않았습니다. 새로 다운로드한 파일은 갱신 시점에 따라 값과 구조가 달라질 수 있습니다.

**원본 CSV는 `.gitignore`의 `data/raw/` 규칙으로 제외되어 GitHub에서 제공하지 않습니다.** 실행하려면 사용자가 위 출처에서 CSV를 다운로드해 지정한 경로에 넣어야 합니다. 이 프로젝트는 데이터의 이용허락 범위나 재배포 권한을 임의로 단정하지 않습니다. 사용·공유 전 다운로드 페이지와 해당 데이터의 이용 조건을 직접 확인하세요.

## 5. 현재 구현된 기능

- `pandas.read_csv()`를 사용하는 CP949 CSV 로더
- 문자열 또는 `Path` 객체로 파일 경로 입력
- DataFrame 반환 및 원본 컬럼 순서 유지
- `dtype=str`, `keep_default_na=False`를 통한 문자열 값 보존
- 최소 필수 컬럼인 `도서관명` 존재 여부 검사
- 파일 없음, 읽기 실패, 인코딩 오류, CSV 파싱 오류에 대한 설명 제공
- 완전히 빈 CSV와 헤더만 있는 CSV의 오류 구분
- 터미널에서 전체 행 수·컬럼 수·모든 컬럼명·첫 5개 행 출력
- `main.py`의 위치를 기준으로 원본 CSV의 절대 경로 계산
- 도서관명 부분 일치, 시도명·시군구명 전체 일치 검색
- 입력한 검색 조건의 AND 조합과 조건별 앞뒤 공백·대소문자 무시
- 도서관별 번호와 빈 줄로 구분한 세로 출력 (이름, 지역, 주소, 평일·토요일 운영시간)
- 실제 존재하는 컬럼 값을 사용하고, 빈값은 화면에서만 `정보 없음`으로 안내
- 0건 안내, 빈 검색 조건과 검색 필수 컬럼 누락 오류 처리
- 원본 DataFrame을 변경하지 않는 검색 결과 복사본 반환
- 합성 데이터를 이용한 pytest 테스트 49개 (로더 9개, 검색 23개, CLI 17개)

로딩 또는 검색 검증 실패 시 실행 프로그램은 오류 메시지를 표준 오류 출력에 기록하고 종료 코드 `1`을 반환합니다. 성공 시 종료 코드는 `0`이며 검색 결과 0건도 정상 종료합니다. 필수 컬럼 검사는 컬럼의 존재 여부만 확인하며, 셀 값의 유효성까지 검사하지 않습니다.

## 7. 프로젝트 설치 방법

### 프로젝트 폴더로 이동

소스 코드를 내려받거나 복사한 뒤, 프로젝트의 상위 폴더에서 다음 명령을 실행합니다. 이미 프로젝트 루트에 있다면 이동은 생략합니다.

```powershell
Set-Location .\public-library-data-tool
```

이후 명령은 모두 `main.py`와 `requirements.txt`가 있는 프로젝트 루트에서 실행합니다.

### 가상환경 생성 및 의존성 설치

새 환경에서는 Python 3.13을 설치한 뒤 가상환경을 생성합니다. 기존 `.venv`가 있다면 생성 명령은 생략합니다.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

가상환경의 Python을 직접 지정하므로 `Activate.ps1` 실행은 필요하지 않습니다.

### 원본 CSV 준비

1. [공공데이터포털의 데이터 페이지](https://www.data.go.kr/data/15013109/standard.do)에서 전국도서관표준데이터를 **CSV 형식**으로 다운로드합니다.
2. 프로젝트 루트에서 아래 명령으로 원본 보관 폴더를 만듭니다.
3. 다운로드한 파일을 `data/raw/전국도서관표준데이터.csv`에 배치합니다. 기존 원본이 있다면 덮어쓰기 전에 별도로 확인하세요.

```powershell
New-Item -ItemType Directory -Path .\data\raw -Force | Out-Null
Test-Path -LiteralPath '.\data\raw\전국도서관표준데이터.csv'
```

파일을 배치한 뒤 `Test-Path` 결과가 `True`인지 확인합니다. 현재 로더는 CP949를 사용하므로, 다운로드 파일의 인코딩이 다르면 오류 내용을 확인해야 합니다. 이 도구는 원본을 자동 변환하거나 대체 데이터를 생성하지 않습니다.

## 8. Windows PowerShell 실행 방법

프로젝트 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe .\main.py
```

현재 원본 파일 기준 출력 일부는 다음과 같습니다.

```text
전체 데이터 행 수: 3,597
전체 컬럼 수: 28

모든 컬럼명:
1. 도서관명
2. 시도명
3. 시군구명
```

실제 프로그램은 28개 컬럼명을 모두 출력하고, 이어서 첫 5개 행의 모든 컬럼을 출력합니다. 첫 5개 도서관명은 다음과 같이 확인했습니다.

1. 경상북도교육청 울릉도서관
2. 경상북도교육청 봉화도서관
3. 충청남도태안교육청태안도서관
4. 충청남도청양교육지원청청양도서관
5. 충청남도보령교육지원청웅천도서관

다른 폴더에서 실행할 때는 가상환경 Python과 `main.py`의 절대 경로를 지정하면 됩니다. 프로그램은 현재 작업 디렉터리 대신 `main.py`의 위치를 기준으로 CSV를 찾습니다. 프로젝트 내부의 `data/raw/`에서 실행하는 경우도 직접 검증했습니다.

### 도서관 검색

| 옵션 | 동작 |
| --- | --- |
| `--name` | 도서관명 부분 일치, 정규식 기호도 문자 그대로 검색 |
| `--sido` | 시도명 전체 일치 (예: 서울특별시) |
| `--sigungu` | 시군구명 전체 일치 (예: 강남구) |
| `--help` | 사용법 표시 |

입력과 비교용 데이터의 앞뒤 공백·대소문자를 무시합니다. 지정하지 않은 조건은 적용하지 않고, 여러 조건은 AND로 적용합니다. 원본 값은 수정하지 않습니다. 공백만 있는 조건은 오류이며, 검색 옵션을 모두 생략하면 기존 구조 조회를 수행합니다.

```powershell
# 도서관명만 검색
.\.venv\Scripts\python.exe .\main.py --name '울릉'

# 시도명만 또는 시군구명만 검색
.\.venv\Scripts\python.exe .\main.py --sido '서울특별시'
.\.venv\Scripts\python.exe .\main.py --sigungu '강남구'

# 두 지역 조건 검색
.\.venv\Scripts\python.exe .\main.py --sido '서울특별시' --sigungu '강남구'

# 도서관명과 지역 복합 검색
.\.venv\Scripts\python.exe .\main.py --name '청양' --sido '충청남도' --sigungu '청양군'

# 검색 결과 0건 확인
.\.venv\Scripts\python.exe .\main.py --name '존재하지않는합성검색어'
```

### 도서관별 세로 출력 예시

`--name '울릉'` 실행 결과에서 CSV 경로 안내를 제외한 부분입니다.

```text
검색 결과: 1건

[1] 경상북도교육청 울릉도서관
지역: 경상북도 울릉군
주소: 경상북도 울릉군 울릉읍 봉래길 128-10
평일: 09:00 ~ 18:00
토요일: 09:00 ~ 17:00
```

복수 결과는 원본 행 순서대로 `[1]`, `[2]`, `[3]`처럼 번호를 붙이고 도서관 사이에 빈 줄을 둡니다. 지역·주소는 해당 컬럼이 있을 때 표시합니다. 시간 값이 비어 있으면 화면에만 `정보 없음`을 표시하고, 요일의 시작·종료 컬럼이 모두 없으면 해당 줄을 생략합니다. 한쪽 시간 컬럼만 없으면 없는 쪽을 `정보 없음`으로 안내합니다. 원본 DataFrame은 변경하지 않습니다.

### 실제 검색 시나리오 실행 기록

2026-10-11, 현재 보관한 3,597행·28컬럼 CSV를 대상으로 PowerShell에서 실행했습니다. 초기 검색 검증에서는 표준 라이브러리 `csv.DictReader`로 원본을 별도 읽고 예상 결과를 계산했습니다. 세로 출력 개선 후에도 동일한 세 검색을 다시 실행해 건수가 유지되는 것을 확인했습니다.

| 시나리오 | 입력 | 예상 결과 | 실제 결과 |
| --- | --- | --- | --- |
| 이름 검색 | `--name '울릉'` | 울릉도서관 1건 | 1건, 종료 코드 0 |
| 지역 조합 | `--sido '서울특별시' --sigungu '강남구'` | 두 지역 조건을 모두 만족하는 27건 | 27건, 종료 코드 0 |
| 이름·지역 조합 | `--name '청양' --sido '충청남도' --sigungu '청양군'` | 청양도서관 1건 | 1건, 종료 코드 0 |

초기 검색 검증에서 세 시나리오의 모든 결과 컬럼 값을 원본 CSV와 대조했습니다. 세로 출력 개선 후에는 검색과 출력 전후 입력 DataFrame 및 결과 DataFrame이 동일함을 확인했습니다. 강남구 결과의 번호는 `[1]`부터 `[27]`까지이며, 울릉도서관의 네 운영시간도 그대로 표시됩니다. 값의 확인 예시는 다음과 같습니다.

| 도서관명 | 소재지도로명주소 | 평일 시작·종료 | 토요일 시작·종료 |
| --- | --- | --- | --- |
| 경상북도교육청 울릉도서관 | 경상북도 울릉군 울릉읍 봉래길 128-10 | 09:00 / 18:00 | 09:00 / 17:00 |
| 충청남도청양교육지원청청양도서관 | 충청남도 청양군 청양읍 칠갑산로1길 15 | 09:00 / 19:00 | 09:00 / 17:00 |

추가로 존재하지 않는 합성 검색어를 실제 실행해 아래 출력과 종료 코드 `0`을 확인했습니다.

```text
검색 결과: 0건
조건에 일치하는 도서관이 없습니다.
```

### 지원 범위와 한계

- 지역은 공식 컬럼 값과 전체 일치해야 합니다. `서울`을 `서울특별시`로 바꾸는 별칭 처리나 오타 보정은 지원하지 않습니다.
- 시군구명만 검색하면 여러 시도의 같은 시군구명이 함께 포함될 수 있습니다. 필요한 경우 시도명도 지정하세요.
- 검색 함수가 반환하는 DataFrame은 원본의 행·컬럼 순서를 유지합니다. CLI는 정해진 항목 순서로 세로 출력합니다. 정렬, 페이지 구분, 결과 파일 저장은 구현하지 않았습니다.
- 빈값·일부 시간 컬럼 누락에 대한 `정보 없음`은 화면용 안내이며 데이터 보정이 아닙니다. 운영시간을 임의로 생성하거나 해석하지 않습니다.
- 긴 주소는 좁은 터미널에서 줄바꿈될 수 있으며, 세로 출력은 결과가 많을 때 스크롤이 길어집니다.
- 검색 함수는 `도서관명`과 실제 적용할 필터의 컬럼만 요구합니다. 지정하지 않은 지역 컬럼은 필수가 아닙니다.
- 운영시각과 휴관일을 근거로 현재 영업 중인지 판정하지 않습니다. `00:00`의 의미도 자동 해석하지 않습니다.

## 9. pytest 테스트 방법 및 실제 결과

프로젝트 루트에서 테스트 임시 파일의 위치를 프로젝트 내부로 설정한 뒤 실행합니다. `TEMP`와 `TMP` 설정은 현재 터미널 세션과 여기서 실행한 프로세스에 적용됩니다.

```powershell
New-Item -ItemType Directory -Path .\.pytest_cache\tmp -Force | Out-Null
$env:TEMP = (Resolve-Path -LiteralPath .\.pytest_cache\tmp).Path
$env:TMP = $env:TEMP

```

## 10. 현재까지 발견한 문제와 해결 과정

| 문제 또는 확인 사항 | 해결 과정·현재 상태 |
| --- | --- |
| 초기 검사 스크립트를 PowerShell에서 Python으로 전달할 때 한글 파일명이 `?`로 바뀜 | PowerShell의 전달 인코딩을 UTF-8로 설정한 뒤 실제 파일을 정상 확인 |
| 원본은 UTF-8로 해독되지 않음 | CP949로 해독 성공을 확인하고 로더에 해당 인코딩 명시 |
| pandas의 자동 변환으로 원래 문자열 표현이 달라질 가능성 | 문자열 타입과 기본 결측치 변환 비활성화를 적용하고 합성 데이터로 검증 |
| 빈 파일과 헤더만 있는 파일의 원인이 다름 | 서로 다른 오류 메시지와 테스트로 구분 |
| 실행 위치에 따른 파일 경로 문제 | `Path(__file__).resolve().parent`를 기준으로 경로 구성 후 다른 프로젝트 내부 폴더에서 실행 검증 |
| 청양도서관의 `운영기관명`이 빈칸 | 원본을 유지했으며, 빈값의 의미와 처리 정책은 다음 단계에서 확인 예정 |
| 옵션 없는 구조 조회의 28개 컬럼 표가 넓어짐 | 구조 조회는 기존 가로 표를 유지하며, 검색 결과 출력만 세로 방식으로 개선 |
| 검색 결과의 운영시간 일부가 화면에서 빈칸처럼 보임 | 각 단계의 `repr()`와 출력 문자열에서 네 값이 보존됨을 확인하고, 한글 가로 표 정렬 문제를 세로 출력으로 개선 |
| 검색어의 `[` 같은 문자가 정규식으로 해석될 가능성 | `regex=False`로 문자 그대로 검색하고 합성 데이터로 검증 |
| 공백만 있는 조건이 전체 결과를 반환할 가능성 | 빈 조건을 명시적으로 거부하고 오류 메시지·종료 코드를 테스트 |
| 빈값이나 일부 시간 컬럼이 없는 결과의 표시 | 실제 값만 읽고 화면용 `정보 없음` 안내·항목 생략을 적용한 뒤 원본 불변과 함께 테스트 |

검색 결과 출력 개선은 다음 순서로 진행했습니다.

1. **문제 발견:** 울릉 검색 결과에서 운영시간 일부가 빈칸처럼 보였습니다.
2. **원인 검증:** 로딩 직후·검색 직후·CLI 출력 직전의 `repr()` 값과 실제 출력 문자열에 `09:00`, `18:00`, `09:00`, `17:00`이 모두 있었습니다. 데이터 손실이 아니라 한글 너비 계산과 터미널 표시 폭에 따른 정렬 문제를 확인했습니다.
3. **출력 개선:** 로더·검색 로직을 유지하고 `main.py`의 검색 결과를 도서관별 세로 출력으로 변경했습니다.
4. **회귀 검증:** 기존 37개를 유지한 전체 49개 테스트가 통과했고, 실제 검색 건수 1·27·1건과 울릉 운영시간을 다시 확인했습니다.

초기 테스트에는 네 운영시간을 모두 가진 CLI 출력 검증이 없었습니다. 또한 문자열 캡처는 터미널의 표시 폭과 줄바꿈을 재현하지 않습니다. 이를 보완해 네 시간의 보존, 요일별 출력, 번호, 빈값·컬럼 누락과 출력 전후 원본 불변을 검증했습니다. 이는 데이터 품질 전반의 검증을 완료했다는 의미는 아닙니다.

PowerShell에서 검사 스크립트를 파이프로 전달할 때 사용한 설정은 다음과 같습니다. 일반적인 `python.exe main.py` 실행에는 필수 설정이 아닙니다.

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new()
```

이 설정은 스크립트 전달에 관한 것으로, 원본 CSV를 CP949로 읽는 설정과는 별개입니다. 원본을 임의로 정제하거나 인코딩을 변경하지 않았습니다.
